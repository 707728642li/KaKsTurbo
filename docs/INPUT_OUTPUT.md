# Inputs, outputs and interpretation

[Home](../README.md#results-you-can-use) · [CLI reference](USAGE.md) · [Raw-CDS tutorial](RAW_CDS_TUTORIAL.md)

## Supported inputs

KaKsTurbo fits **directed codon-aligned pairs under standard genetic code 1**. It accepts KaKs-style AXT, aligned FASTA plus an explicit pair manifest, or a complete directory generated by `prepare`. Compressed `.gz` sequence inputs are supported. The CLI does not infer homology or align raw CDS; the separate MAFFT/PAL2NAL [preparation workflow](RAW_CDS_TUTORIAL.md) provides that upstream step.

### AXT

Each record identifies one request followed by the two aligned coding sequences. Use the [bundled synthetic AXT](../examples/three_pair_smoke.axt) as an executable example:

```bash
./kaksturbo validate --input examples/three_pair_smoke.axt
./kaksturbo run --input examples/three_pair_smoke.axt --output results_axt --backend cpu
```

Pair IDs are preserved exactly. A plain AXT does not supply explicit `seq1_id` / `seq2_id`; these remain missing rather than being guessed from its pair ID.

### Aligned FASTA with directed pairs

The TAB-separated manifest has these columns:

```tsv
pair_id	seq1	seq2
request_01	gene_A	gene_B
request_02	gene_B	gene_A
```

The first whitespace-delimited token of each FASTA header is its sequence ID. The two requests above remain separate directed records. For the bundled example:

```bash
./kaksturbo prepare --input examples/aligned/aligned.fasta \
  --pairs examples/aligned/pairs.tsv --output prepared_demo
./kaksturbo validate --input prepared_demo
./kaksturbo run --input prepared_demo --output results_prepared --backend cpu
```

Keep the complete prepared directory together. Its metadata binds IDs, request order and sequence fingerprints to the aligned input. A separately moved AXT can use `--metadata FILE`; the metadata must match every requested pair. Gap, ambiguous-nucleotide and stop-containing codons are filtered jointly in both members of the pair.

## Primary result schema

`result.tsv` and `results.jsonl` contain the same core information. TSV uses `NA` for unavailable numerical values; JSONL uses `null`. Values are copied from the estimator, not recomputed from rounded display fields.

| Fields | Meaning |
|:---|:---|
| `pair_id`, `seq1_id`, `seq2_id` | Directed request and explicit sequence IDs; unknown IDs are not inferred |
| `method`, `mode`, `backend` | Recorded estimator, numerical mode and execution backend |
| `Ka`, `Ks`, `Ka_Ks` | Nonsynonymous rate, synonymous rate and reported model-averaged ratio |
| `aligned_codons`, `eligible_codons`, `observed_SNP` | Alignment length, retained paired codons and observed nucleotide differences |
| `status`, `reason` | Availability and an explicit reason when a value is unavailable |
| `lnL`, `best_model` | Native reported MA log likelihood and model-criterion choice, when available |
| `iteration_capped_models`, `boundary_models` | Recorded candidate names; an empty list differs from unknown diagnostics |

### Real synthetic example

Selected columns from the accepted Windows rc10 CPU output, rounded to six decimal places:

| pair_id | Ka | Ks | Ka_Ks | status |
|:---|---:|---:|---:|:---|
| forward | 0.066008 | 0.065604 | 1.006154 | available |
| reverse | 0.066008 | 0.065604 | 1.006154 | available |
| identical | NA | NA | NA | unidentifiable |

[Full TSV](../examples/results/three_pair_cpu.tsv), [JSONL](../examples/results/three_pair_cpu.jsonl) and [quality summary](../examples/results/three_pair_cpu_quality.txt) preserve full precision and recorded warnings. The identical pair's zero observed substitutions yield an undefined estimate, not a numeric zero ratio. The plain AXT example has no explicit sequence-ID sidecar, so those ID fields remain empty/null. Linux last digits and gradient flags can differ; see [platform observations](NUMERICAL_SMOKE.md).

## Files in a completed run

| File | Contents |
|:---|:---|
| `result.tsv`, `results.jsonl` | Canonical core results |
| `native_result.tsv`, `native_results.jsonl` | Native estimator output retained for traceability |
| `models.tsv`, `models.jsonl` | Full candidate-model records, including all fourteen slots |
| `pair_statistics.jsonl` | Per-pair reconstruction/statistics and recorded diagnostics |
| `qc.tsv`, `data_dictionary.json` | Input/retained-codon QC and machine-readable field definitions |
| `run_manifest.json` | Input, configuration, engine and output provenance |
| `quality_summary.txt`, `quality_summary.json` | Human-readable and structured coverage/NA/cap/bound/gradient summaries |

`status=available` is not a convergence certificate. Read model weights and diagnostic flags together; a strict projected-gradient threshold of 1e-8 is distinct from the finite-coordinate acceptance gate. [Numerical interpretation](NUMERICAL_VALIDATION.md)

## Optional KaKs_Calculator-compatible export

```bash
./kaksturbo export results_axt --format kaks-calculator --output compatible_export
```

This reads a completed run and writes a separate 22-column table. It neither refits models nor changes the canonical outputs. Missing or unvalidated statistics are NA with cell-level reasons. Layout compatibility does not establish estimator equality; a robust export does not invent a Fisher-test P value. ## Checkpoints and safe relocation

Use a new result directory for each run. `resume` requires the original configuration and compatible release; relocated inputs must match the original bytes. Copy the complete prepared input, and retain checkpoint-referenced chunks until the run completes. A 100% chunk counter precedes final aggregation/commit and is not itself a completed result. See [checkpoint compatibility](MIGRATION.md).
