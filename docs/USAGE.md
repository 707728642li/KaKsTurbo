# CLI guide

Run `./kaksturbo --help` or `./kaksturbo COMMAND --help` from the extracted Linux package. Windows uses `kaksturbo.exe` (or the bundled PowerShell entry for deep installation paths). [Install](../README.md#installation) · [中文完整说明](../USER_GUIDE_ZH.txt)

| Command | Purpose |
|:---|:---|
| `doctor` | Check runtime, native assets and device prerequisites |
| `examples` | Write example inputs to a new directory |
| `prepare` | Normalize aligned input and bind sequence metadata |
| `validate` | Check input syntax, pair identities and metadata before fitting |
| `run` | Fit the requested pairs and write standard results |
| `status DIRECTORY` | Read committed run progress |
| `resume DIRECTORY` | Continue a compatible interrupted run |
| `export DIRECTORY` | Export saved results in a compatible layout without refitting |

## Common run parameters

| Option | Default / accepted values | Purpose |
|:---|:---|:---|
| `--input` | Required | Aligned AXT/FASTA, `.gz` input, or prepared directory |
| `--output` | Required | New output directory |
| `--pairs` | Optional TSV | Explicit `pair_id`, `seq1`, `seq2` mapping for FASTA |
| `--metadata` | Optional JSONL | Byte/identity-checked metadata for prepared AXT |
| `--input-format` | `auto`, `axt`, `fasta` | Input interpretation |
| `--mode` | `robust` (default), `reproduce` | Numerical policy; reproduce is CPU-only |
| `--backend` | `auto` (CPU), `cpu`, `gpu` | Explicit execution choice |
| `--threads` | Up to 16 available logical CPUs by default | CPU workers; Windows 1–32, Linux 1–128 |
| `--device` | `auto`, `cuda:0`, `cuda:1`, GPU UUID | Select one GPU |
| `--chunk-pairs` | 1000; allowed 1–1000 | Pairs per resumable chunk |
| `--max-seconds` | 600 | Per-chunk wall-clock timeout, not a convergence threshold |
| `--method` / `--genetic-code` | `MA` / `1` | Supported estimator and genetic code |
| `--quiet` | Off | Hide progress |
| `--json` | Off | Machine-readable command outcome/errors |

Worker counts are not physical-core counts. For controlled benchmarks, topology/affinity must be specified separately. Changing worker allocation does not change the fourteen-model or FP64 contract.

## CPU and GPU

```bash
./kaksturbo doctor --backend cpu
./kaksturbo run --input examples/three_pair_smoke.axt --output cpu_run --backend cpu --threads 8

nvidia-smi
./kaksturbo doctor --backend gpu --probe-gpu
./kaksturbo run --input examples/three_pair_smoke.axt --output gpu_run --backend gpu --device cuda:0
```

`doctor --probe-gpu` initializes the driver after admission; it does not fit sequences. See [device requirements and error guidance](DEVICES.md).

## Check and continue a run

```bash
./kaksturbo status cpu_run --json
./kaksturbo resume cpu_run
./kaksturbo resume cpu_run --max-seconds 1200
```

Resume can increase the chunk timeout or relocate identical input files using `--input`, `--pairs` and `--metadata`. It cannot silently change the scientific settings, worker configuration or engine identity. Completed chunks are verified and reused. [Version compatibility](MIGRATION.md)

## Export without fitting

```bash
./kaksturbo export cpu_run --format kaks-calculator --output compatible_run
```

Use a new export directory outside the original run. The 22-column layout and NA reasons are documented in [the export mapping](COMPATIBLE_EXPORT.txt).

## Progress and output

Terminal progress reports committed pair count, throughput, elapsed time, ETA and stage. Output aggregation may continue after the last chunk. Normal runs produce TSV/JSONL and quality summaries; no HTML is generated by default. For exact result fields and examples, see [input/output](INPUT_OUTPUT.md).
